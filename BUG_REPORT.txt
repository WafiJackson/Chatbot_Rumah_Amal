1. [BUG - FIXED] Hardcoded "localhost:3000" pada resolve chatId

   Perbaikan: URL sekarang memakai WAHA_ENDPOINT (configurable), konsisten
   dengan pemanggilan WAHA lainnya. Diverifikasi: saat WAHA_ENDPOINT diarahkan
   ke stub lokal, resolve chatId ikut berhasil (sebelumnya selalu gagal karena
   tetap mengarah ke localhost:3000).

2. [SECURITY/CONFIG - FIXED] Fallback API key hardcoded di kode
   File: app/routes/bot_webhook.py
   Perbaikan: Default WAHA_API_KEY diubah dari string rahasia "amalmaximal123"
   menjadi string kosong, dengan log warning saat startup jika env var belum
   diset. Aplikasi tidak lagi diam-diam berjalan dengan kredensial yang ada di
   git history.

3. [MAINTAINABILITY - FIXED] Nomor rekening bank di-hardcode berulang
   File: app/routes/bot_webhook.py
   Perbaikan: Ditambahkan konstanta modul BANK_REKENING_INFO, dipakai di
   ketiga lokasi (info rekening, lanjut sesi, pilih program selesai) sehingga
   hanya ada satu sumber kebenaran.

   app/services/llm_agent.py.

=====================================================
BAGIAN B - TEMUAN DARI USER TESTING (SIMULASI CHAT LANGSUNG)
=====================================================

1. [BUG - FIXED] Sapaan dobel "Kak Kak"
   File: app/admin_scripts.py (fungsi ambil_balasan) - root cause utama
   File: app/routes/bot_webhook.py - 4 lokasi lain dengan pola sama (fungsi
   pembantu baru _sapaan_dengan_nama)
   Perbaikan: sapaan gender ("Kak"/"Bapak"/"Ibu") tidak lagi digabung dengan
   nama jika nama kosong ATAU nama tersebut (setelah dibersihkan) sama persis
   dengan kata sapaannya sendiri - kasus ini terjadi saat WAHA tidak mengirim
   pushname/notifyName dan kode fallback ke placeholder "Kak".
   Verifikasi ulang (webhook sungguhan): kirim "assalamualaikum" tanpa nama
   kontak -> balasan sekarang "Assalamu'alaikum Kak! Selamat datang..."
   (sebelumnya "Kak Kak"). Kasus nama asli (mis. "Budi Santoso") tetap tampil
   normal ("Bapak Budi Santoso") - tidak ada regresi.
   Self-check: test_sapaan_fix.py (5 assertion, semua lulus).

2. [BUG - FIXED sebagai efek dari perbaikan A.1] Respons macet 8-16 detik
   saat WAHA tidak reachable
   Penyebab utamanya adalah dua host WAHA yang berbeda dipanggil untuk pesan
   yang sama (WAHA_ENDPOINT yang benar vs localhost:3000 yang salah), masing-
   masing gagal dengan caranya sendiri dan menambah latensi. Setelah A.1
   diperbaiki, resolve chatId dan pengiriman pesan memakai host yang sama,
   sehingga tidak lagi gagal dobel akibat dua alamat berbeda.

3. [BUG - FIXED, sama dengan A.1] localhost:3000 hardcode menyebabkan resolve
   chatId gagal terus-menerus
   Sudah diperbaiki di Bagian A.1 di atas.

4. [BUG - FIXED] Pesan kosong/whitespace membuat bot gagal total membalas
   File: app/main.py
   Perbaikan: stdout & stderr di-reconfigure ke UTF-8 (errors="replace") saat
   startup aplikasi, sebelum modul lain yang memakai print()/logger di-import.
   Ini mencegah UnicodeEncodeError merusak seluruh request webhook saat
   balasan berisi emoji dan konsol/host tidak memakai UTF-8 (mis. cp1252 di
   Windows).
   Verifikasi ulang (webhook sungguhan): kirim pesan body kosong -> sebelumnya
   {"status":"error", ...} tanpa balasan terkirim; sekarang
   {"status":"sukses","intent":"tidak_diketahui"} dan balasan (berisi emoji)
   berhasil di-print dan dikirim ke WAHA.
